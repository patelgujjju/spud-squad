# Prototype engine contract

The engine starts at elapsed time 0 and advances only when the caller supplies time. Public transitions copy their input and return `{ state, events }`. `advance` processes every relevant deadline in chronological order, even when a caller jumps past several events. Splitting a jump into smaller advances produces the same state and events.

- A successful movement starts a 150 ms hop. The position stays on its source tile until landing; the facing changes when the hop starts. Walls, map boundaries and levers block movement. A blocked move leaves facing unchanged, because facing follows the last successful movement. Initial facing is RIGHT.
- During a hop, the first owned press takes the one buffer slot. Later owned presses are dropped. A buffered command runs after landing unless Spud dies or finishes. GRAB uses the facing at execution time.
- Shared owners pressing the same button in the same level-relative 100 ms tick count once. A repeat from the same owner is still subject to the normal hop/buffer rules. Ownership and running/dead/finished status are checked before recording input.
- All valid owned inputs count toward Button Masher, including buffer overflows. Cross-owner duplicates do not count. Fryer Feeder uses the most recent recorded input before death, including an overflow; an unowned or dead-state press never changes blame. Tied awards list all tied players. There is no Fryer Feeder when no player caused a death.
- Coincident events land first, then check hazards, then execute buffered input, then process a conveyor deadline. Landing exactly as a slicer turns on is lethal; leaving its tile exactly then is safe. A press received at that instant is processed after scheduled events, so it cannot cancel an already due death.
- Belts push every 400 ms of continuous residence on enabled belt tiles. Moving between adjacent belts preserves the schedule; leaving the belts resets it. An automatic push cannot interrupt a hop and that scheduled push is skipped if a hop is still in progress. Blocked pushes retry at the next deadline. Belts use the same 150 ms hop as manual movement.
- Slicer cycles start with `onMs` active, followed by `round(offMs × groupFactor)` inactive. `phaseMs` offsets that level-time cycle. The last 400 ms of the inactive interval warn of the next activation. Disabling and re-enabling a slicer does not restart its clock. Group factor is fixed from the player count at level start.
- GRAB toggles all of a lever's linked doors, belts and slicers, including doors previously opened with a key. Levers are solid fixtures. One key opens one currently closed door. Key pickups, consumed keys, key effects on doors and collected Golden Chips persist after death. Checkpoints snapshot lever-controlled device states, which reset on respawn. There are no crates in M1.
- Death clears the hop and buffer and respawns after exactly 1500 ms at the latest checkpoint, or at the start if none was reached. Hazard clocks keep running during death. Blame is cleared on respawn until another valid press arrives.
- Entering the exit finishes at landing time. Hero Press belongs to the player whose command reached it; conveyor exits use the latest recorded presser. One star is awarded for finishing, a second for finishing strictly below the group-adjusted par, and the third for also collecting the Golden Chip. Chips alone do not give three stars.

The schema intentionally rejects mechanics outside the approved M1 set. Level objects must match their map symbols; slicers and levers require object metadata, and lever targets must be valid doors, belts or slicers. Maps need one exit and a safe start.

The assignment helper includes the future STOP/JUMP column of the design table, but M1 level files only accept the five basic buttons. Seeds control the per-level player shuffle. Six to ten players share buttons evenly.
